## 요약

- **치명은 없다.** 저장 순서는 설계 §2.5 그대로다. 파이썬 수준에서 끊은 약 200곳에서 모두, 다음 실행이 백업으로 되살려 같은 지문으로 끝나거나 설계대로 L24·거절로 멈췄다. 예외 둘(split 재적용, restart 일지)은 아래 C-2·C-6 에 있다.
- **D1~D7 분류와 종료 코드는 §3.9·§8.4 와 맞는다.** 아래 정상 자료 장면에서 거짓 D 는 나지 않았다.
  - 휴장일, 연말연초(2027.csv 늦음 → D7, 2026.csv 빠짐 → D4)
  - 서머타임 07:10, 국내 20:00·22:29, 미국 08:40 보조, 국내 07:40 보조
  - 5봉 밀림은 0, 6봉은 6
- **실행기가 엔진을 잘못 부르는 곳은 찾지 못했다.** `prev_cal_date`·`calendar`·`halted`(보유·대기 포함)·커밋마다 새로 만든 HEAD 지문·종목군 지문·`allowed` 를 모두 맞게 넘긴다.
- **운영 전에 고칠 것(중요) 5가지**
  - 환경 오류(디스크 가득 등)가 L 로 기록된다 → 3개월을 잃을 수 있다(C-1).
  - `corp-action --split` 은 다시 쳐도 거절하지 않고 한 번 더 적용한다(C-2).
  - 장부를 읽기 전에 난 L24·관문 거절은 `start_date` 가 비어 `status` 에 세어지지 않는다(C-3).

  - `replay_pass.json` 에서 옛 줄이 사라지면 지난 봉 전체가 L22 가 된다(C-5). 다음 단계 `h1_replay.py` 와의 약속 문제다.
- **시험**: §6 ID 는 대부분 실제 장면으로 덮여 있다.
  - "여러 날 끝까지" 시험은 디스크의 장부·calendar.jsonl·판정 기록만으로 `check_ledger`·`check_pair` 를 다시 돈다.

## 그대로 둬도 되는 것 (확인함)

- **커밋 순서**: 판정 기록(엔진이 묻는 순간 append + fsync) → `backup/<옛 HEAD.run_id>/`(임시 폴더에 다 쓴 뒤 이름 바꿈) → 장부 6개(+ 바뀐 meta) `.tmp` → fsync → replace → 폴더 fsync → HEAD.
  - E1 에서 run·delist·amend·start·되살리기 중 끊김을 모두 지문까지 되살렸다.
  - 백업 열쇠는 HEAD 의 `run_id` 이고, 따라잡기 두 번째 봉은 `<run_id>.2` 를 쓴다. 지금 HEAD 의 백업은 지우지 않고 최근 10개를 남긴다.
  - corp-action·amend-rules 도 같은 `commit()` 을 쓴다. 장부를 읽을 때 남은 `.tmp` 는 잠금 아래에서 지운다.
- **`.starting/`**: 다 쓴 뒤 `os.replace` 로 이름을 바꾼다. 남은 폴더는 다음 start 가 지우고 다시 하며, 재시작으로 세지 않는다(E1 start 30곳 모두 정상).
- **잠금**: 모든 명령이 잡는다(status 포함). 잠금 없이 쓰는 것은 잠금 시간 초과 한 줄(`runs.jsonl`, O_APPEND)뿐이다. 잠금 fd 는 자식 프로세스(claude)에 넘어가지 않는다(PEP 446).
- **경로**: `h1_path` 가 조각·심볼릭 링크를 확인하고, `_root` 는 운영 `state/` 와 그 위 폴더를 거절한다. 운영 장부를 건드리지 않는다(T-F1b).
- **준비 순서와 종료 코드**: 실행 순서는 5→7→6→8→9 이고, 종료 코드는 D1·D2·D3·D4·D5·D6 → 4, D7 → 7(앞 봉까지 저장), 밀린 봉 > 5 → 6, 관문·규칙 → 3, 장부 없음 → 8 이다. 사전 조건 위반은 4(설계 §10.2c 와 같음).
- **D 판정의 세부**
  - D7 은 확인용 대형주의 최신 봉 확정 시각(KS200 22:30 KST, SPY 16:15 ET)으로 판단한다.
  - D4 는 처리한 날짜와 calendar.jsonl 마지막 정상 줄을 함께 본다. D·멈춤 줄은 기준으로 쓰지 않는다.
  - D6 은 정지일 marks 를 "그 날짜 이하 마지막 확정 종가"와 비교하고, 상장폐지 종목을 빼고, 분할·정정을 반영한다.
- **기업 행위 명령**
  - 상장폐지: `last_date ≤ 장부 last_date` 일 때만 받고, `last_close` 를 비우면 마지막 marks 를 쓰고 그 출처를 적는다. 두 번 등록은 거절한다.
  - 정정 확정: (날짜, 칸, 옛 값, 새 값)을 적고, 그 뒤 D6 은 그 칸을 새 값과 비교한다. 새 값이 없는 칸은 거절한다.
- **amend-rules**: 관문을 거치고, 앞줄 그대로·뒤에만 추가·날짜 오름차순·시행일 > last_date 를 확인한 뒤 meta 만 바꾸는 커밋을 한다.
- **지문·관문**: `code_hash` 는 없는 파일(지금은 `h1_report.py`·`h1_replay.py`)을 None 으로 넣는다. `env` 는 python·pandas·numpy·ta·FinanceDataReader 버전을 담는다. 관문은 (지문, env_key) 짝으로 비교하고, `meta.rules` 는 JSON 왕복 값으로 비교한다.
- **④-나 재료**: `errors.jsonl` 의 지문은 "저장하려던" 장부의 지문이다. 같은 봉을 다시 처리하면 같다(시험 있음).
- **늦은 봉 기록**: 하루 기록의 `late`·`mode`, `runs.jsonl` 의 `late_bars`·`bars`·`bar_modes` 에 남아 창 전체 10봉 판정에 쓸 수 있다. status 에도 `늦은 봉 n/10` 으로 보인다.
- **운영 시각 확인**: 국내 23:05·07:40, 미국 07:10·08:40 이 모두 llm 이고 늦은 봉이 아니다(E8, T-DST, T-LLMTIME).
- **CLI**: argparse 오류는 1 로 돌려 2(L)와 겹치지 않는다. 화면은 한국어다. launchd 로그에 run_id·S·마지막 봉·처리할 봉·봉마다 방식/LLM 호출 수/L·경고 수·장부 줄·저장 HEAD·요약·종료 코드 뜻이 남는다. L 은 문제 목록, D 는 사유, 예상 밖 오류는 traceback 까지 남는다.
- **"여러 날 끝까지" 시험**: 디스크에서 읽은 장부·calendar.jsonl·판정 기록만으로 `check_ledger`·`check_pair` 를 다시 돈다. L3·L6(그날 시세 필요)과 L18·L22(종목군 지문)는 빠져 있는데, 앞의 둘은 설계상 오프라인으로 볼 수 없는 것이다.
