## 1. 문제 목록

### A-1 (중요) 국내 후보 표시가 `005930(삼성전자)` 로 바뀌어, 팀장이 그 글을 `code` 로 돌려주면 판정이 조용히 버려진다

- **위치**: `analyst.py` `_build_prompt_h1` 의 `label()`(81~84행)과 JSON 틀 `"code": "<종목>"`(96행), `h1.py` `Leader._ask_and_record` 의 `item = result.get(code)`(602행), `analyst.analyze_logged` 의 `{it["code"]: it …}`(252행).
- **무엇이 틀렸나**: 운영 프롬프트는 후보 줄 앞이 `- 005930:` 이라 "`<종목>` = 그 글자"가 하나로 정해졌다. H1 프롬프트는 `- 005930(삼성전자):` 인데 JSON 틀은 그대로 `"<종목>"` 이다. 팀장이 줄 앞 글을 그대로 베껴 `"code": "005930(삼성전자)"` 나 `"삼성전자"` 로 답하면, 답은 왔는데 열쇠가 안 맞아 그 종목은 `missing_in_reply` 폴백이 된다. 직접 확인(탐침 `review6a/probe/probe_label.py`, 가짜 subprocess):

  | 답의 code | 판정 기록 | team 에 가는 값 |
  |---|---|---|
  | `"005930"` | source=llm, status=ok, verdict=veto | veto 반영 |
  | `"005930(삼성전자)"` | source=**fallback**, status=**missing_in_reply**, verdict=None | `{}` → **veto 가 사라지고 규칙대로 매수** |
  | `"삼성전자"` | 위와 같음 | 위와 같음 |

  얼마나 자주 그럴지는 진짜 `claude` 없이는 알 수 없다(대부분은 `005930` 으로 답할 것으로 보이지만 보장은 없다). 문제는 (가) 이 커밋이 새로 만든 실패 길이고, (나) 국내에만 생기며, (다) 이 커밋의 목적(판정 기록의 질)을 바로 깎고, (라) 어떤 시험·재현·맥 확인 목록도 보지 않으며(맥 목록 3번은 `claude -p "JSON 하나만"` 같은 일반 프롬프트), (마) start 뒤에 고치면 코드 동결 위반 → 재시작이라는 점이다. 폴백이 20% 를 넘으면 보고서가 "팀장 판정 대표성 없음"을 단다(실패 사유는 아님).
- **고칠 방법**(start 전에, 하나 이상):
  1. JSON 틀을 분명히: `"code": "<위 목록의 종목 코드 그대로(괄호 앞, 예 005930)>"`. 또는 이름을 다른 칸으로: `- 005930: 이름=삼성전자 신호사유=…` (이러면 "운영 글 + 이름" 모양도 유지).
  2. H1 쪽에서만 너그럽게 맞추기: `Leader._ask_and_record` 에서 답 열쇠가 `todo` 코드에 없으면 `"005930(삼성전자)"` → 괄호 앞, 이름 → 코드(`markets.KR_UNIVERSE`)로 한 번 더 찾기. 원래 글은 `verdict_raw` 처럼 기록. (`analyze_logged` 결과 모양은 그대로 두는 편이 `analyze()` 와 같다는 약속을 덜 흔든다.)
  3. 맥 리허설(D-6) 또는 맥 확인 목록 3번에서 **진짜 H1 프롬프트**로 한 번 물어(`analyst.analyze_logged(…, context={"market":"kr",…}, cwd=…)`) 답 `code` 가 `005930` 모양인지, `status` 가 `ok` 인지 확인한다.

### A-3 (보통) 미국 종목 이름을 뺀 근거가 사실과 다르고, 사용자 결정("날짜·시장·종목명")의 일부만 구현했다

- **위치**: `h1.py` `Leader.prompt_context`(539행, 미국 `names = {}`), 설계 §10.1 Q4 이유 칸("미국 이름은 start 때 인터넷으로 이름 목록을 받아 종목군 파일 모양을 바꿔야 해서 넣지 않음(티커 자체가 널리 알려진 이름)").
- **무엇이 틀렸나**:
  - "인터넷으로 이름 목록을 받아야" — 미국 종목군은 start 때 `screener.universe(40)` 가 `fdr.StockListing("S&P500")` 로 **이미 받는다**. 그 표(FinanceDataReader `wikipedia/listing.py` 48행)는 `Symbol, Name, Sector, Industry` 를 같이 준다. 새 인터넷 호출이 필요한 것이 아니라, 같은 표에서 `Name` 을 버리고 있는 것이다. "종목군 파일 모양을 바꿔야" 는 맞다(`universe/us.json`·L22 모양 확인, 또는 따로 파일 하나).
  - "티커 자체가 널리 알려진 이름" — S&P500 을 **무작위로** 섞은 40종목이라 AAPL 같은 이름만 나오지 않는다. S&P500 에는 한 글자 티커(J·L·O·D·A 등)나 덜 알려진 티커도 있어, 이름 없이 티커만 보면 팀장이 다른 회사로 착각할 수 있다.
  - 사용자가 고른 것은 "H1 에서만 날짜·시장·**종목명** 넣기"(의도 대조 D-1)였는데, 미국 종목명을 뺀 것은 진행 담당의 결정이다. 오류노트 E-43 의 교훈("위임은 정해진 것을 뒤집는 것이 아니다")과 같은 모양이다. 뒤 커밋의 `docs/h1-forward-run.md` §2 D-1 에 "미국은 티커 그대로"가 사용자에게 보이게 적힌 것은 좋지만, 그 근거가 위처럼 정확하지 않다.
- **고칠 방법**: (가) 사용자에게 "미국은 티커만"을 받아들일지 정확한 근거로 다시 확인받거나, (나) start 때 종목군을 고정하는 같은 자리에서 `Symbol → Name` 을 함께 저장(예: `h1_data` 에 이름까지 돌려주는 함수, `universe/us.json` 에 `names` 칸 또는 `universe/us_names.json`, 재시작해도 그대로)하고 `prompt_context` 가 그것을 읽게. 운영 `screener.universe()` 는 건드리지 않는다. 어느 쪽이든 설계 Q4 이유 칸을 사실대로 고친다.

### A-4 (보통) 11절 국내 문장 "지금 큰 회사 목록이라 생존편향이 있다"는 포워드에 맞지 않는 말이다

- **위치**: `h1_report.py` 1674~1676행(11절 "생존편향:" 줄, 두 시장).
- **무엇이 틀렸나**: 생존편향은 "지금까지 살아남은 회사만 골라 **과거**를 돌려 볼 때" 생긴다(안내서 06 용어표도 "살아남은 회사만 보고 판단"). R2 는 2015~2026 을 2026년 목록으로 돌려 봐서 생존편향이 있었다. 포워드는 S 날 알 수 있는 목록으로 고정하고 **앞으로** 가며, 창 안에 상장폐지가 나도 종목군에서 빼지 않는다(`corp-action --delist`). 그래서 이 3개월 결과에는 그런 생존편향이 없다. 지금 문장은 초보에게 "국내 포워드 결과는 믿을 수 없다(미국은 괜찮다)"는 엉뚱한 비대칭을 준다. 맞는 한계는 (가) 대형주만 본다 — 시장 전체로 넓혀 읽으면 안 된다, (나) R2 의 좋은 결과 일부는 생존편향 덕이었다(R2 §5-1) — 이 포워드가 그것을 고쳐 주지는 않는다.
- **고칠 방법**: 예) 국내 "- 종목군: KR_UNIVERSE 32종목(2026년 하반기 코스피 대형주)으로 시작 때 고정했다. 앞으로의 기간이라 '살아남은 회사만 고른' 생존편향은 없지만, 대형주만 보므로 시장 전체의 결과로 읽으면 안 된다. R2 에서 국내 결과가 좋았던 데는 지금 목록으로 과거를 돌린 생존편향도 있었다." 미국도 머리말을 "종목군:" 으로 바꾸고 같은 뜻을 한 줄. `h1_report.py` 는 CODE_FILES 이므로 맥 재현·태그 전에.

### A-5 (경미) 11절 트레이너 문장: 국내 보고서에도 미국 숫자만 있고, "백분위 12%"를 수익률로 읽을 수 있다

- **위치**: `h1_report.py` 1680~1681행.
- **무엇이 틀렸나**: 숫자 자체는 맞다(R2 REPORT 핵심 표: 미국 R0 12%, 2014 상위 20 16%). 그러나 같은 문장이 국내 보고서에도 그대로 나온다. R2 국내는 **88%**(마라토너 93%, 스프린터 8%, 파이오니어 15%)로 "무작위보다 나은 쪽이지만 95% 에 못 미침"이었다. 국내 보고서 독자는 자기 시장 숫자를 못 보고 "국내는 괜찮았나?"를 알 수 없다. 또 "백분위 12%·16%"는 초보가 "수익률 12%"로 읽기 쉽다.
- **고칠 방법**: 시장별 문장 + 풀이. 예) 미국 "…트레이너 매매 시점을 같은 횟수·기간의 무작위 시점 매매 1,000번과 견주면 12%·16% 보다만 나았다(50% = 동전 던지기, 95% 를 넘어야 약한 근거)", 국내 "…88%(마라토너 93%)로 나은 쪽이었지만 95% 에 못 미쳤고, 스프린터는 8% 였다".

### A-6 (경미) "내리면 A1 이 A0 보다 더 잃는다"는 R2 와 조금 다르다

## 6. 쉬운 말 요약

- 이 커밋은 두 가지를 했다. ① H1 에서만 팀장(Claude)에게 "**언제**(기준 날짜)·**어느 시장**·**무슨 회사**(국내만)"를 알려 준다. ② 월간 보고서의 "한계" 설명을 고쳤다.
- **운영(진짜 쓰는 프로그램)은 바뀌지 않았다.** 운영 팀장에게 가는 글은 한 글자도 안 바뀌었고, 그걸 지키는 시험(골든)이 제대로 지킨다.
- 날짜는 **맞는 날짜**다(신호를 낸 그날, 주문은 다음 날 아침 시가). 앞으로의 일을 미리 알려 주는 일도 없다. 두 장부(A0·A1)가 같은 판정을 쓰는 성질도 그대로다.
- 고칠 것 중 가장 중요한 것: 국내 종목을 `005930(삼성전자)` 처럼 보여 주는데, 팀장이 답에 그 글을 그대로 베끼면 프로그램이 "답이 없다"고 보고 **팀장의 '사지 마(veto)'를 버린다**. start 전에 답 틀을 분명히 하거나 너그럽게 맞추고, 맥에서 진짜 팀장으로 한 번 확인하자.
- 시험이 "운영 길 전체"를 보지 않아, 날짜를 하루 틀리게 보내는 실수를 못 잡는다. 시험 하나를 더하면 된다.
- 미국은 회사 이름을 빼고 티커만 보낸다. 빼는 이유로 적은 "인터넷으로 따로 받아야 한다"는 사실이 아니다(이미 받는 표에 이름이 있다). 사용자가 그래도 괜찮은지 정하거나 이름을 넣자.
- 보고서의 "국내는 생존편향이 있다"는 이번 3개월(앞으로의 기간)에는 맞지 않는 말이다. "대형주만 본다"가 맞는 한계다. 또 국내 보고서에는 국내 숫자(88%)를, "백분위"에는 쉬운 풀이를 붙이자.
- 이 밖에 "Q4 는 보류 / 프롬프트는 운영과 같다"가 남은 문서 몇 곳을 고치면 된다. 모두 `h1_report.py`·`analyst.py`·`h1.py` 를 고치는 일이라 **맥 재현·태그·start 전에** 해야 한다.
