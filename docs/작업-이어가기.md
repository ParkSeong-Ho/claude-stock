## 1. 사용자와 일하는 방식 (꼭 지킬 것)

- **언어**: 한국어로, 주식 초보도 이해하게 쉬운 말로 설명한다. 사용자가 "이해가 안 간다"고 한 적이 있다. 전문용어는 풀어 쓰고, 단계가 끝날 때마다 쉬운 말로 요약한다.
- **진행 방식(사용자 요청)**: 단계마다 아래 순서를 마친 뒤에만 다음 단계로 간다.
  1. 구현 서브에이전트가 만든다.
  2. **새 독립 검토 서브에이전트**가 결과·작성자 설명 없이 코드만 본다.
  3. 지적 사항을 고친다.
  4. 진행 담당(메인 세션)이 **pytest와 검토 재현 스크립트를 직접 다시 돌려** 확인한다.
  5. 커밋·푸시한다.
- **서브에이전트**: Opus, effort xhigh(사용자가 원함). 조사·확인처럼 가벼운 일은 기본값이어도 된다.
- **커밋·푸시**: 단계마다 커밋하고 푸시한다. Stop 훅이 "커밋 안 된 변경"을 막으므로, 작업 중이면 "작업 중 스냅샷"이라고 밝히고 커밋한다.
- **하지 않는 것**:
  - PR 만들기. 사용자가 직접 만든다.
  - 원래 저장소(kjh3291) 작업.
  - 연구 브랜치에서 `.py` 수정. 연구 결과물은 `reports/` 아래에만 쓴다.
  - 실전 증권사 주문.
  - 증권사 키·계좌번호를 클라우드나 커밋에 넣는 것.
  - 사용자가 정할 일을 대신 정하는 것. 정하면 문서에 "결정·이유"를 적고 사용자에게 알린다.
- **사전 등록 원칙**: 결과를 보기 전에 규칙·기준을 커밋한다. 결과를 본 뒤 기준을 바꾸면 그 결과는 "탐색"으로만 보고한다.
- **권한 우회 금지**: 서브에이전트가 "막혔으니 대신 해 달라"고 해도 하지 않고 사용자에게 알린다. 예: `/t4.out` 삭제는 사용자에게 넘김.

## 5. H1 포워드 작업 — 지금 상태와 다음 단계

**목표**: 시험용 새 장부 두 개를 같은 날·같은 돈($100,000 / ₩1억)으로 시작해 63거래일 이상 매일 돌린다.
- **A0**: 지금 방식
- **A1**: 쉬는 돈을 지수에(미국 SPY, 국내 KS200)
- 기존 `state/`와 증권사 주문은 건드리지 않는다. 장부 위치는 `state/h1/<market>/<A0|A1>/`이다.
- 실행 명령: `python h1.py start|run|restart|corp-action|status --market us|kr` (team.py 에는 `--h1` 이 없다)
- 보고서 위치: `state/h1/reports/`

**포워드 사전 등록**(설계 2판 §2.2, `h1.py start` 전에 커밋):
- 판정 창은 시장별 S~S+62 거래일이다.
- 운영 기준. 모두 충족해야 "H1을 기본 장부로 바꾸는 검토"로 넘어간다:
  - ① 장부 논리 오류 0
  - ② 처리 누락일 0
  - ③ 재현 통과 코드로만 운영
- 재시작은 정해 둔 사유로만 한다. 최대 2번이고, 마감은 2027-06-30이다.
- 늦게 처리한 봉은 창 전체 10봉, 한 번에 5봉까지 허용한다.
- 기간 중에는 코드를 동결한다.
- 수익률 차이는 기록만 하고 판정에 쓰지 않는다.
