## 1. 사용자와 일하는 방식 (꼭 지킬 것)

- **언어**: 한국어로, 주식 초보도 이해하게 쉬운 말로 설명한다. 사용자가 "이해가 안 간다"고 한 적이 있다. 전문용어는 풀어 쓰고, 단계가 끝날 때마다 쉬운 말로 요약한다.
- **진행 방식(사용자 요청)**: 단계마다 아래 순서를 마친 뒤에만 다음 단계로 간다.
  1. 구현 서브에이전트가 만든다.
  2. **새 독립 검토 서브에이전트**가 결과·작성자 설명 없이 코드만 본다.
  3. 지적 사항을 고친다.
  4. 진행 담당(메인 세션)이 **pytest와 검토 재현 스크립트를 직접 다시 돌려** 확인한다.
  5. 커밋·푸시한다.
- **서브에이전트**: Opus, effort xhigh(사용자가 원함). 조사·확인처럼 가벼운 일은 기본값이어도 된다.
- **커밋·푸시**: 단계마다 커밋하고 푸시한다. Stop 훅이 "커밋 안 된 변경"을 막으므로, 작업 중이면 "작업 중 스냅샷"이라고 밝히고 커밋한다.
- **하지 않는 것**:
  - PR 만들기. 사용자가 직접 만든다.
  - 원래 저장소(kjh3291) 작업.
  - 연구 브랜치에서 `.py` 수정. 연구 결과물은 `reports/` 아래에만 쓴다.
  - 실전 증권사 주문.
  - 증권사 키·계좌번호를 클라우드나 커밋에 넣는 것.
  - 사용자가 정할 일을 대신 정하는 것. 정하면 문서에 "결정·이유"를 적고 사용자에게 알린다.
- **사전 등록 원칙**: 결과를 보기 전에 규칙·기준을 커밋한다. 결과를 본 뒤 기준을 바꾸면 그 결과는 "탐색"으로만 보고한다.
- **권한 우회 금지**: 서브에이전트가 "막혔으니 대신 해 달라"고 해도 하지 않고 사용자에게 알린다. 예: `/t4.out` 삭제는 사용자에게 넘김.
