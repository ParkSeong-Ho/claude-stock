## 그대로 둬도 되는 것

- **R2 와 같은 숫자.** 위 표와 같이 W1 4조합·W2 2조합에서 M1~M4·M5′·over_slots 가 완전히 같다. 다음은 맞게 구현돼 있다.
  - `u_net`, `avail·(1−1e-9)`, `min(units, short/u_net·(1+1e-9))`, 쓸어 담기 문턱 1·줄임 1e-12→1e-9→1e-6
  - 지수 매도세 0, `kr_sell_tax` 표(R2 와 같은 값), `shares_within_cap(start_cash, …)`
  - S 입금만 → S+1 a→b→c→d→e
  - 정지 종목 마지막 종가 평가, 보유일수·판단 쉼, 그림자 서킷 prev = 전날 하루 기록
- **운영 동작 보존.**
  - 갈고리 G0·G1·G2·G4(`cands0` 는 apply 바로 앞, `note_leader` 는 주문 뒤)·G5 가 설계 §3.2 와 같다.
  - `h1=None` 경로는 들여쓰기 외에 바뀐 것이 없고 골든이 덮는다(돌연변이로 확인).
  - team 은 h1 을 import 하지 않는다(T-ENTRY 새 프로세스 시험).
- **미리보기·시각.**
  - `cut_frame`→`StrictFrames`, `scan_frames(asof=t)`, 자른 시세로 team ② 지표를 쓴다.
  - `next_open`(다음 평일, 서머타임 시험 있음)이 맞다.
  - 봉 시작 `mode`, 묻기 직전마다 시각 재확인(`went_late`·`late_calls`)이 맞다. 3 에서 늦은 봉 6·`late_calls` 6 을 확인했다.
  - 보유만 한(대기 없는) 종목의 시가 NaN 행은 오류가 아니다(실데이터에서 확인).
- **판정 기록·팀장.**
  - 열쇠 `"<시장>|<날짜>|<트레이너>|<종목>"` 로 두 장부가 같은 판정을 쓰고, A1 은 기록에 없는 후보만 묻는다.
  - 줄마다 `fsync`, 새 파일이면 폴더 `fsync` 도 한다. 반쯤 쓴 마지막 줄만 잘라 낸다.
  - `missing_in_reply`·각 폴백 상태가 있고, `note` 는 500자로 자른다.
  - 정리된 판정의 team 적용(veto 빠짐·hold 보류·확신도·정렬 `conviction or 0` 안정 정렬)과 점검 L19 가 실데이터 가짜 팀장 실행에서 L 0 이었다.
- **장부 내용 지문.**
  - 설계 정의대로다: `schema`·`h1` 머리·하루 기록 실행 메모 6칸·지갑 이름을 빼고, `sort_keys`·`allow_nan=False` 로 sha256 을 낸다.
  - 해시 씨앗을 바꿔도, 늦은 봉으로 다시 처리해도 같다.
  - 지갑 기록에는 늘 거래일을 넘겨 벽시계 시각이 섞이지 않는다.
- **JSON 왕복.** 매 봉 왕복을 거친 장부가 R2 와 비트까지 같다(지수 단위 상대 차 0). 주식 수량은 int 로 돌아온다.
- **점검의 거짓 양성(위 B-1·B-2 밖).** 실데이터에서 L 0 이었다.
  - 국내 정지를 가로지른 대기·보유(W2), S·S+1, 늦은 봉, 판정 기록 재사용, 시가 없는 보유 행
  - 가짜 팀장의 veto·hold·낮은 확신도·문자열 확신도·답 빠짐
- **점검의 음성 대조.** L1~L23 마다 일부러 넣은 잘못이 그 코드로 나온다(위 B-7 의 일부 하위 항목 빼고).
