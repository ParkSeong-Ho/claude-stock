## 2. 문제 목록

### B-1 (보통) 미국 이름 받기가 실패하면 3개월 창 전체(재시작 포함)가 이름 없이 가고, 어디에도 기록되지 않는다

- **위치**: `h1_data.universe_names`(예외를 안에서 삼키고 `_say` 한 줄만), `h1._source_names`(예외일 때만 `log.note` — 운영 `names()` 는 예외를 내지 않으므로 이 길은 운영에서 안 탐), `h1._start_locked`(종목군 줄에 이름 개수 표시 없음), 재시작은 종목군 파일을 그대로 씀(설계 213행).
- **무엇이 틀렸나**:
  - 사용자 결정 D-1 은 "날짜·시장·**종목명**"이다. 미국 이름은 start 순간 한 번 받는 위키백과 표뿐인데, 그때 한 번 실패하면(일시 오류, 429, 표 칸 이름 변경 → KeyError 등) 종목군 파일에 `"names": {}` 가 적히고 그 sha256 이 `meta.universe_sha256` 에 묶인다. 나중에 채우면 L22 이므로 **창이 끝날 때까지 되돌릴 수 없고, 재시작해도 같은 파일을 쓰니 이어진다.**
  - 남는 흔적은 start 화면의 한 줄 "(종목 이름 목록 받기 실패 …)" 뿐이다. 탐침(가짜 출처가 빈 이름을 줌): `runs.jsonl` 에 이름 이야기가 전혀 없고 start 요약도 "새로 받은 12종목을 고정"만 찍는다. `status`·월간 보고서에도 없다. 사용자는 미국 팀장이 3개월 동안 이름 없이 판단했다는 것을 모를 수 있다.
  - start 는 사람이 손으로 한 번 하는 일이고, 이름 받기 바로 앞에서 같은 표(종목군)를 막 받았으므로 "다시 시도"가 싸다. 종목군 파일은 start 가 끝나야 쓰이므로 거절하고 다시 해도 깨끗하다.
- **고칠 방법**(start 전에, 하나 이상):
  1. 미국 start 에서 이름이 종목군의 대부분(예 38/40 미만)이면 **start 를 거절**(D2 처럼 "이름 목록을 받지 못함 → 잠시 뒤 다시 start"). 사용자가 일부러 "이름 없이"를 고를 수 있게 옵션 하나(`--no-names`)를 두면 결정이 기록된다.
  2. 아니면 최소한 `universe_names` 가 실패 사유를 돌려주게 해 `log.note` 로 `runs.jsonl` 에 남기고, start 요약에 "이름 n/40" 을 찍고, run 문서 start 확인 항목에 "`universe/us.json` 의 `names` 가 40개" 를 더한다.

### B-2 (보통) 새 시험이 `_reply_item` 의 경계와 운영 이름 받기 함수를 지키지 않는다 — 돌연변이 4개가 pytest 전체 통과

- **무엇이 틀렸나**(복사본 돌연변이, pytest 전체 939개):

  | # | 바꾼 것 | 결과 | 뜻 |
  |---|---|---|---|
  | m01 | `_reply_item` 을 `k.strip().startswith(code)` 로(앞글자만 보기) | **통과** | 탐침: `A` 가 `{"AAPL": veto}` 를, `GOOG` 가 `{"GOOGL": veto}` 를 가져간다 — **엉뚱한 종목에 veto**. `GOOG`·`GOOGL` 은 둘 다 S&P500 이라 같은 40종목·같은 묶음에 들 수 있고, 팀장이 둘을 한 회사로 보고 한 줄만 답하면 실제로 생길 모양 |

- **고칠 방법**:
  1. `_reply_item` 시험에 음성 경우를 더한다: todo `["A","AAPL"]`·답 `{"AAPL": veto}` → `A` 는 missing_in_reply·`AAPL` 은 veto, todo `["GOOG","GOOGL"]`·답 `{"GOOGL (Alphabet A)": veto}` → `GOOG` 폴백, 답 `{"A.O. Smith": veto}` → `A` 폴백. (m01·m13 을 잡는다.)

### B-3 (경미) 이름 값 검사가 없다 — 줄바꿈이 든 이름은 가짜 후보 줄을 만들고, 긴 이름도 그대로 들어간다

- **위치**: `h1_data.universe_names`(문자열이고 빈칸이 아니면 통과), `h1._universe_blob`·`read_universe_names`(같음), `analyst._build_prompt_h1.name_part`(그대로 붙임).

## 5. 쉬운 말 요약

- 이 커밋은 지난 검토(6a)에서 나온 12가지를 고쳤다. **운영(진짜 쓰는 프로그램)은 한 글자도 안 바뀌었고**, 그걸 지키는 시험(골든)이 제대로 지킨다.
- 가장 중요했던 것 — 팀장이 `005930(삼성전자)` 처럼 답하면 "사지 마(veto)"가 버려지던 문제 — 는 **고쳐졌다.** 이제 종목 줄은 `- 005930: 이름=삼성전자` 이고, 답에 이름이 붙어 와도 프로그램이 코드를 찾아 판정을 살린다. 실제 경로로 돌려 확인했다. **엉뚱한 종목에 veto 가 붙는 길은 지금 코드에는 없다.**
- 다만 그 "엉뚱한 종목에 안 붙인다"를 지키는 시험이 없어서, 누가 찾기 규칙을 "앞글자만 보기"로 단순하게 바꾸면 `GOOG` 가 `GOOGL` 의 veto 를 가져가도 시험이 모른다. 시험 몇 줄이면 된다(B-2).
- 미국 회사 이름도 이제 넣는다. 그런데 start 순간 이름 받기가 한 번 실패하면 **3개월 내내 이름 없이** 가고, 그 사실이 어디에도 안 남는다. start 는 사람이 한 번 하는 일이니, 이름을 못 받으면 "잠시 뒤 다시 start" 하라고 멈추는 게 낫다(B-1). 이름에 줄바꿈 같은 이상한 글자가 섞이면 그대로 팀장 글에 들어가니, 받을 때 한 줄로 다듬고 길이를 자르자(B-3).
- 보고서 한계 문장은 대부분 맞게 고쳐졌다. "무작위와 비교"의 뜻을 R2 와 똑같이(같은 종목·금액·기간, 사는 날만 무작위) 적고, 국내 88% 도 "95% 에 못 미쳐 근거가 아니다"를 붙이자(B-6).
- 나머지는 작은 것들: 빈칸만 붙은 코드도 찾게, "이름 붙은 답을 찾아 썼다"를 기록에 남기기, 인계 메모·시험 지도·설계 표의 옛 말 고치기 등.
- 모두 `h1.py`·`h1_data.py`·`h1_report.py`·`analyst.py` 를 고치는 일이라 **맥 재현·태그·start 전에** 해야 한다(start 뒤에는 코드 동결).
