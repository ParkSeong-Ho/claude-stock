## 2. 점검 항목별 답 (요청 1~9)

1. **충실도.** 식·순서·여유값·문턱·비용은 sim_team 과 같다: `need = E·n + E·n·fee`(sim_team.py:579-580 = paper_wallet.py:96-99), `u_net`(482-485), `avail·(1−1e-9)`(585), `min(held, short/u_net·(1+1e-9))`(498), 쓸어 담기 `≥ 1`·줄임 1e-12→1e-9→1e-6(502-513), 상한 기준 = 시작 예산(572-574), 지수 매도세 0(490·500), 매도 먼저(533-543). 현금 부족 날은 지수를 안 팔고 보류(586-589) — 설계와 같음. 세 트레이너 순서는 지갑이 독립이라 숫자에 영향 없음(팀장 기록만 A0 가 먼저 묻는 차이). 종가 평가 기준(정지 종목 마지막 종가 + 지수 종가, 매도 비용 안 뺌) 도 같음(684-691, K2). **안 맞는 곳**: 시작(X2), 국내 세율(m1), 서킷(X1). 이자: R2 A0 는 이자를 현금에 넣어 매수·서킷에 씀 → H1 은 계산값(근사, Q10) — 문서에 적혀 있고 사전 등록 7.5-3("기록")에 어긋나지 않음. 지갑 로그 `금액`은 소수 2자리로 반올림되므로(paper_wallet.py:151) 점검이 지갑 로그를 쓰면 안 된다.
2. **미리보기·시각.** KS200 22:30·종목 16:00·asof 자르기·미국 16:15 ET·07:10 KST(=17:10 EST/18:10 EDT) 는 맞다. 구멍: 늦은 실행의 LLM(I6), 데이터 지연(I1), KS200 멈춤(I4). Q8 이유("지난 가격으로 못 산다")는 따라잡기 체결에도 똑같이 해당하지만, 그쪽은 주문이 t 이전 자료로 정해진 고정 규칙이라 문제 없음 — 이유 문장만 다듬으면 됨.

## 4. 구현하면서 지킬 것

- `h1.fill` 은 `_fill_sell`/`_fill_buy`/`_raise_cash`/`_sweep_to_index` 의 **식 순서까지** 그대로 옮긴다(`exec_px*n + exec_px*n*fee`, `min(held, short/u_net*(1+1e-9))`, `u > 0` 일 때만 매도). 지수 단위에 `int()`·`round()` 금지, 화면만 6자리.
- `wallet.value(prices)` 를 부르기 전에 모든 보유(지수 포함)의 가격 키가 있는지 assert(R14). `team._prices` 에는 엄격한 cache(m6).
- 판정 기록은 장부보다 먼저 추가·fsync, 장부는 커밋 지점 하나(I7). 그림자 서킷은 전날 day row `value` 로(team.py:270 이 덮어쓰기 전 값).
- 모든 오류 등급 점검은 (a) 일부러 잘못 넣은 장부로 그 코드가 나는 음성 대조, (b) 재현 창·2018 국내 창·합성 정지에서 거짓 양성 0 — 둘 다 통과해야 넣는다. 점검은 지갑 로그(반올림됨)가 아니라 `fills` 로.
- 골든은 **코드를 한 줄도 바꾸기 전에** 847ad13 에서 만든다. `--h1` 없으면 `h1` 이 `sys.modules` 에 없음을 시험.
- 관문 거절·자료 정지도 `runs.jsonl` 에 남긴다(시장 폴더 밖). 시각은 전부 시간대 있는 값, 시험은 KST 고정 시계(10:00 KST 늦은 실행 포함).
- 재현 하네스는 연구 브랜치를 임시 폴더에 풀고 모듈 경로를 확인(설계 그대로), 하위 클래스 덮어쓰기는 하네스 파일 안에서만.
