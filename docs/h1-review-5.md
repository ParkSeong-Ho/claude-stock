## 1. 요약

**재현이 "자기와 비교"가 되는 길은 찾지 못했다.** 하네스는 R2 를 새 임시 폴더에 풀어 `python -I -B` 로만 돌고, 모듈 다섯 개가
임시 폴더 안에서 읽혔는지 확인한다(가짜 R2 로 확인한 시험도 실패할 수 있는 시험). R2 브랜치의 `team.py`·`main.py`·`paper_wallet.py`·
`screener.py`·`analyst.py`·`markets.py` 는 지금 저장소와 다르고(브레인 셋·`risk_guard.py`·`metrics.py` 는 같음), 기준값은 매번 새로
만든다(저장된 결과·캐시 재사용 없음). 허용 오차(상대 1e-9, 현금 절대 1e-6, 체결가·주식 수 정확히)와 K1(마지막 봉 판단만 뺌)은 설계
그대로다. 실제 결과는 설계보다 훨씬 여유 있게 같다(체결 현금 차 ≤ 3.7e-9, 매일 값 상대 차 ≤ 4.3e-16, 지수 단위 차 0).

W3 는 의미가 있다. 두 쪽이 같은 합성 시세·같은 가짜 브레인 파일(sha 확인)을 읽고, s1·s3·s4·s5·s6 은 M1~M5′ 가 같다는 사실 때문에
기준값도 같은 길을 지났다고 말할 수 있다. 세율 경계 `>=`→`>`, 그림자 서킷 하루 한도 0.07→0.085, 쓸어 담기 문턱 1→0.5 는 모두
W3 가 잡았다(실데이터 창은 앞의 둘을 못 잡음 — W3 가 꼭 필요한 이유).

통과 기록·관문은 맞게 돈다. 실패·일부 창·코드가 바뀐 경우 기록하지 않고, 기록은 봉인과 함께 들어가며, 관문은 그 줄로 열리고
코드가 바뀌면 3 으로 닫힌다.

**고쳐야 할 것은 둘이다.**
- **P-1**: K9 가 국내 세율 표를 "R2 표와 완전히 같음"으로 본다. 그래서 ⑥-ii(세율 표 뒤에 줄 추가)를 한 코드는 **재현을 통과할 수 없고**,
  통과 기록이 없으니 `amend-rules` 도 관문에서 막힌다. 설계가 허용한 길이 막혀 재시작밖에 없다. `h1_replay.py` 는 CODE_FILES 라
  창이 시작된 뒤에는 고칠 수 없으므로 **첫 start 전에** 고쳐야 한다.
- **P-2**: 비교 항목(M1~M7)이 보유 상태(보유일수 `days_held`·매수가·주식 수)를 직접 보지 않고, W3 가짜 브레인은 보유 상태를 보지 않는다.
  정지 중 "판단 쉼" 규칙(보유일수를 안 늘림)이 어긋나도 R2 차등 비교는 W2·W3 모두 "같음"이다. 재현 안에서는 `h1_check` 의 L15 하나가
  잡고 있을 뿐이다(L15 까지 같이 틀리면 재현 통과 — pytest 는 잡지만 관문은 재현 기록만 본다). 재현이 "R2 와 같은 규칙"을 보증한다는
  목적과, W3 가 "실데이터에 없는 정지 길"을 맡는다는 목적에 비해 빈 곳이다. 이것도 start 뒤에는 고칠 수 없다.

나머지는 경미하다(빈 장면 확인, NaN 이 통과하는 비교, R2 커밋 고정 없음, 진행 표시·Ctrl-C·실패 원인 표시, 시험의 돌연변이 검출력).
