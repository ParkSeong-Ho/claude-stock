## 0. 파일과 실행 명령

| 파일 | 내용 |
|---|---|
| `sim_team.py` | 팀 단위 시뮬레이터. 진입점은 `run(Config(...)) -> dict` 하나 |
| `check_team.py` | 오프라인 점검. PASS/FAIL을 찍고, 하나라도 실패하면 종료 코드 1 |
| `data/us/` | R0 데이터 복사본: `origin/research-2026-11-04:reports/research-2026-11-04/data/`의 21개 파일과 `universe.json` (`git show`로 바이트 그대로) |
| `data/us_pit/`, `data/kr/`, `data/rates/` | 단계 0에서 받은 것(STAGE0.md §8). 이번에는 손대지 않았다 |

```bash
# 저장소 루트에서
/root/.venv-cs/bin/python -I reports/research-r2-2026-11-04/check_team.py          # 점검 전부 (약 2분)
/root/.venv-cs/bin/python -I reports/research-r2-2026-11-04/sim_team.py us A1 "2018 조정"   # 한 조건만 돌려 보기
```

`-I`(격리 모드)로 실행하면 현재 폴더가 import 경로에 들어가지 않는다. 그래서 두 스크립트가 저장소 루트와 자기 폴더를 경로에 직접 넣는다. 받은 데이터 폴더에 있는 파일은 import 되지 않는다.

단계 2에서 쓰는 예:

```python
import sim_team as S
r = S.run(S.Config(market="us", period="전체 2015-26", arm="A1", n_random=1000))
r["metrics"]            # 수익률, MDD, 주식·지수·현금 비율, 매수·매도·보류 수, 비용, 이자, 지수 B&H·동일비중 B&H 대비
r["refs"]               # 지수 B&H(R0 방식), 20종목 동일비중 B&H, G11 10개월선 추세추종
r["daily"]              # 날짜별: 합계·트레이너별 평가액, 주식/지수/현금 비율, 매수·매도·지수 다리·보류 수, 비용, 이자
r["trades"], r["fills"], r["skips"], r["orders"], r["events"]   # 거래·체결·보류(사유 포함)·주문·서킷/재배분 사건
r["random"]["전체"]     # H1-4 무작위 시점 대조 (actual, random_mean, pct_below …)
```

설정 이름:
- `arm`: `A0` / `A1`(=H1) / `A1T`(=H2) / `A2` / `G11`(참고선) / `IDX`(점검용 지수 소수 단위 B&H)
- `cb`: `none` / `current` / `staged`. H3에 쓰고, A0·A1에서만 받는다.
- `realloc=True`: H4. A1에서만 받는다.
- `market`: `us` / `us_pit` / `kr`
- `period`: 국면 이름 또는 `(시작, 끝)`
- `total=10_000`: §7.0의 "$10,000 참고 결과"

## 1. 하루 순서 (team.py `run_trainer`와 같은 순서)

**시가 (봉 t)**, 트레이너 지갑(슬리브)마다:
1. 국면 첫날이면 시작 금액을 입금한다.
2. 어제까지 낸 주문 가운데 **오늘 그 종목 봉이 있는 것**만 처리한다. 국내 거래정지로 봉이 없으면 다음 거래된 봉까지 그대로 둔다(A5).
3. ① 주식 매도 → ② (그날 대기 자산이 현금이면) 지수를 전부 판다 → ③ 주식을 산다. 대기 자산이 지수면 **현금으로 모자란 만큼만** 지수를 판다 → ④ (그날 대기 자산이 지수면) 남은 현금을 전부 지수로 산다.
4. (H4) 분기 첫 거래일이면 모든 트레이너의 체결이 끝난 뒤 지수 단위를 옮긴다.

**종가 (봉 t)**, 지갑마다:
1. 이자: 현금 × 연%/100/252 (A1·A2 규칙의 금리)
2. 평가: `PaperWallet.value`(현금 + 주식 + 지수). 현금·주식·지수를 따로 더한 값과도 맞춰 본다.
3. (H4용) 월말이면 월 초과수익을 기록한다.
4. 판단은 국면 마지막 봉에서는 하지 않는다(R0와 같음).
   - ② 보유 종목 매도 판단: 오늘 그 종목 봉이 있고 대기 주문이 없을 때만 한다.
   - ③ 서킷: 지금 서킷(`risk_guard.CircuitBreaker` 그대로) 또는 H3 단계 서킷
   - ④ 신규 후보: 보유 수 + 매수 대기 주문 수가 5보다 작을 때, universe 순서로 고른다. 60봉 미만 종목은 뺀다(A7). 다음 시가에 체결할 주문으로 남긴다.

## 3. 구현 선택 (사양이 비어 있거나 두 가지로 읽히는 곳)

- **I1 같은 시가에서의 순서와 상계.** 순서는 주식 매도 → (현금 대기인 날) 지수 전부 매도 → 주식 매수 → (지수 대기인 날) 남은 현금 전부 지수 매수다.
  - 같은 날 매도 대금은 같은 트레이너의 매수에 먼저 쓴다. 지수는 차액만 사고판다.
  - 사전 등록 문구를 글자 그대로 따르면 같은 시가에 지수를 사고 다시 팔게 된다. 그러면 비용을 두 번 낸다.
  - 국내에서 거래정지로 밀린 옛 주문이 있으면, team.py는 대기 목록 순서대로 처리한다. 여기서는 항상 매도를 먼저 한다.
- **I2 A1 매수 가능 여부.** 필요 금액(`PaperWallet.buy`와 같은 식)이 현금 + 지수를 팔면 받을 돈보다 크면, 지수를 팔지 않고 "현금 부족"으로 보류한다. 지수는 (필요 − 현금) × (1+1e-9)를 받을 만큼 판다. 조금 남는 돈은 다시 지수로 간다.
- **I3 10개월선이 아직 없을 때.** 월말이 10개 모이기 전에는 대기 자산을 지수로 둔다(A1과 같음). 해당 구간은 다음과 같다.
  - 미국 2015-17·전체: 2015-03-31 ~ 2015-10-30. 신호는 2015-11-02 시가부터 쓴다.
  - 국내 2015-17·전체: 2015-01-02 ~ 2015-05-29
  - 월말은 지수 거래일 달력에서 "다음 거래일이 다른 달인 날"이다. 거래소 달력은 미리 아는 정보로 본다.
  - 데이터 마지막 날은 월말로 보지 않는다.
  - 국면 첫날의 상태는 그 전 마지막 월말의 신호를 따른다.
- **I4 이자 시점과 일수.** 매 종가에, 그날 시가 거래 뒤 남은 현금에 붙인다. 국면 첫날에도 붙는다.
  - 국내도 /252로 했다. A2에는 일수가 없다. 국내 거래일은 1년에 약 245~248일이라 이자를 약 2% 덜 준다.
  - A1의 남은 현금(1 미만)에도 이자가 붙는다. 무시할 크기다.
- **I5 H4 종목상한의 기준 금액.** 마지막으로 몫이 바뀐 날의 배정액을 쓴다(새 몫 × 그날 시가 기준 팀 합계). 몫이 한 번도 안 바뀌었으면 시작 예산을 쓴다(team.py와 같음).
- **I6 H4 이동 계산.** 그날 시가 체결이 모두 끝난 뒤, 시가로 평가한다. 그날 봉이 없는 종목은 마지막 종가로 평가한다.
  - 목표와 현재의 차이만큼 옮긴다. 주는 쪽은 자기 지수 단위까지만 준다. 받는 쪽은 모자란 금액의 비율대로 나눠 받는다.
  - "몫이 바뀌면"은 새 몫이 이전 몫과 1e-12보다 크게 다를 때로 정했다.
- **I7 H4 이동에는 비용이 없다.** 팀 안에서 지수 단위만 옮기기 때문이다.
- **I8 H4 통계.**
  - t = 평균 / 표본표준편차(ddof=1) × √n. 표준편차가 0이면 t = 0으로 둔다.
  - 트레이너 월 수익률은 시간가중으로 잰다. 재배분하는 날은 시가 전후로 나눠 계산한다. 지수 월 수익률은 월말 종가끼리 잰다.
  - 첫 달은 국면 시작(시작 금액, 첫날 시가)을 기준으로 잰다. 그래서 짧을 수 있다. 미국 2015-17·전체는 첫 "달"이 2015-03-31 하루뿐이다.
  - n은 그 국면 안의 월 수다.
- **I9 H3 하루 −7%.** "기존 하루 −7% 규칙은 그대로 둔다"를 risk_guard 그대로, 즉 **전량 정리 + 영구 정지**로 읽었다. 다른 해석도 가능하다(§4 P2).
- **I10 H3 쉬는 기간 세기.**
  - 종가 T에 d ≤ −20%이면 T+1 시가에 정리한다. 종가 T~T+19에는 매수 주문을 내지 않는다. 그래서 T+1~T+20, 20거래일 동안 매수 체결이 없다.
  - 종가 T+20에 고점을 그 종가 평가액으로 다시 잡고, 절반 상한으로 다시 시작한다. 그 종가부터 주문을 낼 수 있다.
  - 쉬는 동안에는 d를 계산하지 않는다(다시 걸리지 않게). 하루 −7% 규칙은 계속 본다.
  - 원래 상한으로 돌아가는 것은 평가액이 고점을 넘을 때뿐이다(같으면 아님). d가 −10% 위로 돌아와도 새 고점 전까지는 절반 상한이다.

  - 절반 상한 여부는 주문을 낼 때(그 종가 상태로) 정하고, 체결할 때 쓴다.

- **I12 참고선.**
  - 동일비중 B&H: 국면 첫날까지 상장된 종목만 넣는다. 각 종목을 그날 이후 첫 봉 시가에 사서, 마지막 종가에서 매도 비용을 뺀 값으로 평가한다. 국내는 끝 날짜의 세율로 뺀다.
  - 지수 B&H: R0처럼 정수 단위로 산다(`metrics.buy_and_hold`).
- **I13 무작위 대조(가산형 근사).**
  - 기여 = Σ_거래 [N × (g_종목 − g_지수) − 더 낸 비용]. 각 항목은 다음과 같다.
    - N = 주식 수 × 진입 시가
    - g = 청산 체결 시가 / 진입 체결 시가. 끝까지 보유했으면 마지막 종가를 쓴다. 지수도 같은 날짜로 잰다.
    - 더 낸 비용 = N × (주식 매수 비용률 + 지수 매도 비용률) + N·g_종목 × (주식 매도 비용률(그날 세율) + 지수 매수 비용률)
    - 끝까지 보유한 거래의 청산 쪽은 N·g_종목 × 주식 매도 비용률 − N·g_지수 × 지수 매도 비용률이다.
  - 무작위 1,000번: 각 거래의 종목·N·보유 봉 수는 그대로 두고, 진입 봉만 들어갈 수 있는 범위에서 균등 무작위로 바꾼다.

    - 거래끼리는 독립이다(겹쳐도 됨). 끝까지 보유한 거래를 앞으로 옮기면 중간에 청산된다(R0와 같은 처리).
  - 백분위는 "무작위 합 < 실제 합"인 비율이다(≤도 같이 낸다). 시드는 20261104다.
